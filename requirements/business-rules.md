# Каталог бизнес-правил

В каталоге бизнес-правила классифицируются по пяти типам:

- **Факты** — верные утверждения о бизнесе на определённый момент времени, описывающие связи и отношения между важными бизнес-терминами
- **Ограничения** — правила, определяющие, какие действия или операции запрещены, обязательны либо доступны только при выполнении установленных условий
- **Активаторы операций** — правила, которые при наступлении определённого события или выполнении определённого условия инициируют выполнение действия
- **Выводы** — правила, на основании известных фактов создающие новый производный факт. Обычно записываются в формате «если — то», где результатом является факт, а не действие
- **Вычисления** — правила, преобразующие существующие данные в новую информацию с использованием математических формул или алгоритмов

## Правила формирования слотов
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-SLOT-01 | Слоты формируются только для рабочего дня расписания | Ограничение |
| BR-SLOT-02 | Слот должен полностью находиться внутри рабочего интервала дня расписания | Ограничение |
| BR-SLOT-03 | Слот не должен пересекаться с недоступным периодом дня расписания | Ограничение |
| BR-SLOT-04 | Слот не должен пересекаться с временным интервалом активной записи | Ограничение |
| BR-SLOT-05 | Продолжительность слота определяется продолжительностью выбранной процедуры | Факт |
| BR-SLOT-06 | Время окончания слота вычисляется как сумма времени начала слота и продолжительности выбранной процедуры | Вычисление |
| BR-SLOT-07 | Если процедура не помещается полностью в свободный интервал, такой интервал не считается доступным слотом | Вывод |
| BR-SLOT-08 | Первый слот свободного временного интервала начинается со времени начала этого интервала | Вычисление |
| BR-SLOT-09 | Время начала каждого следующего слота равно времени окончания предыдущего слота | Вычисление |

## Правила онлайн-записи
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-BOOKING-01 | Запись может быть создана только после подтверждения клиентом | Ограничение |
| BR-BOOKING-02 | Запись может быть создана только для доступного слота | Ограничение |
| BR-BOOKING-03 | Временные интервалы активных записей не должны пересекаться | Ограничение |
| BR-BOOKING-04 | После создания активной записи выбранный временной интервал считается недоступным для других клиентов | Вывод |
| BR-BOOKING-05 | Каждая запись должна иметь уникальный токен доступа | Ограничение |
| BR-BOOKING-06 | Просмотр и отмена записи клиентом допускаются только по уникальному токену доступа | Ограничение |
| BR-BOOKING-07 | Фиксированная стоимость определяется по цене процедуры на момент записи | Вычисление |
| BR-BOOKING-08 | Для подтверждения записи клиент должен корректно заполнить имя и номер телефона | Ограничение |
| BR-BOOKING-09 | Для подтверждения записи клиент должен выбрать категорию, процедуру, доступную дату и свободный слот | Ограничение |
| BR-BOOKING-10 | Для подтверждения записи клиент должен дать согласие на обработку персональных данных | Ограничение |

## Правила управления процедурами и категориями процедур
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-PROCEDURE-01 | Процедура со статусом `available` доступна для онлайн-записи | Факт |
| BR-PROCEDURE-02 | Процедура со статусом `unavailable` недоступна для онлайн-записи | Факт |
| BR-PROCEDURE-03 | В MVP мастер может выбирать категории процедур только из преднастроенного справочника | Ограничение |
| BR-PROCEDURE-04 | В MVP мастер не может создавать новые категории процедур | Ограничение |
| BR-PROCEDURE-05 | Мастер может изменять категорию, статус, название, описание, стоимость и длительность процедуры | Ограничение |

## Правила отмены записи мастером или клиентом
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-CANCEL-01 | При отмене записи ее статус изменяется на `canceled` | Активатор операции |
| BR-CANCEL-02 | После отмены записи ее временной интервал может снова считаться доступным, если соблюдены правила формирования слотов | Вывод |
| BR-CANCEL-03 | После наступления времени начала записи клиент не может отменить ее по ссылке | Ограничение |
| BR-CANCEL-04 | Отмененная запись не считается активной | Вывод |

## Правила уведомлений
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-NOTIFY-01 | После создания записи должны быть инициированы уведомления клиенту и мастеру | Активатор операции |
| BR-NOTIFY-02 | Если запись отменил мастер, должно быть инициировано уведомление клиенту | Активатор операции |
| BR-NOTIFY-03 | Если запись отменил клиент, должно быть инициировано уведомление мастеру | Активатор операции |
| BR-NOTIFY-04 | За 24 часа до времени начала активной записи должно быть инициировано напоминание клиенту | Активатор операции |
| BR-NOTIFY-05 | Новое уведомление имеет статус `created` | Факт |
| BR-NOTIFY-06 | Статус уведомления должен соответствовать результату отправки | Ограничение |
| BR-NOTIFY-07 | Если уведомление не отправлено, должна быть зафиксирована ошибка отправки | Активатор операции |
| BR-NOTIFY-08 | Ошибка отправки уведомления не изменяет статус созданной или отмененной записи | Ограничение |

## Правила каналов связи
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-CHANNEL-01 | В MVP для клиента доступен только канал связи типа `phone` | Ограничение |
| BR-CHANNEL-02 | При создании записи номер телефона клиента сохраняется как активный канал связи | Активатор операции |
| BR-CHANNEL-03 | В MVP мастер не может создавать новые типы каналов связи | Ограничение |
| BR-CHANNEL-04 | Мастер может выбирать тип канала связи только из преднастроенного справочника | Ограничение |
| BR-CHANNEL-05 | Мастер может изменять значение и статус отображения канала связи | Ограничение |
| BR-CHANNEL-06 | Клиенту отображаются только активные каналы связи мастера с заполненным значением | Ограничение |
| BR-CHANNEL-07 | У мастера может быть не более одного канала связи каждого типа | Ограничение |

## Правила пользователей, регистрации и доступа
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-USER-01 | В MVP клиент не проходит регистрацию и не имеет личного кабинета | Ограничение |
| BR-USER-02 | Для одного клиента хранится одна запись с именем, номером телефона и `user_type = client` | Факт |
| BR-USER-03 | Если клиент с указанным номером телефона уже существует, новая запись о клиенте не создается | Ограничение |
| BR-USER-04 | Если клиент с указанным номером телефона не найден, создается запись с `user_type = client` | Активатор операции |
| BR-USER-05 | Мастер имеет заранее созданную учетную запись с `user_type = master` | Факт |
| BR-USER-06 | Доступ к личному кабинету мастера разрешен только авторизованному мастеру | Ограничение |
| BR-USER-07 | В MVP самостоятельное восстановление пароля мастера недоступно | Ограничение |
| BR-USER-08 | После 3 последовательных неуспешных попыток авторизации вход в учетную запись мастера блокируется на 60 минут | Ограничение |
| BR-USER-09 | Во время временной блокировки мастер может дождаться окончания 60 минут либо обратиться к администратору системы для восстановления доступа | Ограничение |
| BR-USER-10 | Если мастер не может восстановить доступ после завершения блокировки, он должен обратиться к администратору | Ограничение |

## Правила настройки расписания
| **Идентификатор** | **Определение правила** | **Тип правила** |
|---|---|---|
| BR-SCHEDULE-01 | Для рабочего дня расписания мастер должен указать время начала и окончания работы | Ограничение |
| BR-SCHEDULE-02 | Для нерабочего дня время начала и окончания работы не учитывается | Ограничение |
| BR-SCHEDULE-03 | Для дня расписания с признаком `is_working = false` слоты не формируются | Вывод |
| BR-SCHEDULE-04 | Дата считается доступной для онлайн-записи, если день расписания является рабочим и на эту дату имеется хотя бы один доступный слот | Вывод |
| BR-SCHEDULE-05 | Периоды расписаний одного мастера не должны пересекаться между собой | Ограничение |
| BR-SCHEDULE-06 | Недоступный период должен полностью находиться внутри рабочего интервала дня расписания | Ограничение |
| BR-SCHEDULE-07 | Недоступные периоды одного дня расписания не должны пересекаться | Ограничение |
| BR-SCHEDULE-08 | Изменение рабочего интервала дня расписания, создание или изменение недоступного периода не должны приводить к пересечению с активными записями | Ограничение |
