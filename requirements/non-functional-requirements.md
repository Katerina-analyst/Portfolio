# Перечень нефункциональных требований

## 1. Удобство использования

### NFR-01. Понятность интерфейса

| **ID** | **Требование** |
| --- | --- |
| NFR-01.01 | Названия элементов интерфейса не должны содержать названия таблиц и полей БД, внутренние коды статусов и названия API-параметров |
| NFR-01.02 | Сообщение об ошибке должно содержать понятное пользователю описание причины невозможности выполнения операции без отображения внутренних технических деталей системы |
| NFR-01.03 | Если пользователь может самостоятельно устранить ошибку, сообщение должно содержать указание на необходимое действие |

---

## 2. Производительность

### NFR-03. Скорость отклика

| **ID** | **Требование** |
| --- | --- |
| NFR-03.01 | Время от выбора процедуры до отображения списка доступных дат не должно превышать 3 секунд |
| NFR-03.02 | Время от выбора даты до отображения списка свободных временных слотов не должно превышать 3 секунд |
| NFR-03.03 | Время от отправки клиентом корректно заполненной формы до отображения результата создания записи не должно превышать 3 секунд |

---

## 3. Доступность и устойчивость сервиса

### NFR-04. Доступность и устойчивость онлайн-записи

| **ID** | **Требование** |
| --- | --- |
| NFR-04.01 | Сервис онлайн-записи должен быть доступен не менее 99,5% времени в течение календарного месяца |
| NFR-04.02 | Недоступность сервиса отправки уведомлений не должна приводить к отказу создания, отмены или изменения статуса записи |

---

## 4. Целостность и сохранность данных

### NFR-05. Согласованность данных записи

| **ID** | **Требование** |
| --- | --- |
| NFR-05.01 | Операция создания записи должна завершаться либо сохранением записи и всех данных, создаваемых в рамках этой операции, либо отсутствием любых изменений |
| NFR-05.02 | Операция отмены записи должна завершаться либо сохранением статуса `canceled` и даты и времени отмены, либо отсутствием любых изменений |
| NFR-05.03 | При одновременных запросах на создание записей для одного временного интервала система должна обеспечить создание не более одной активной записи на этот интервал |

### NFR-06. Резервное копирование и восстановление

| **ID** | **Требование** |
| --- | --- |
| NFR-06.01 | Резервное копирование всех данных БД должно выполняться не реже одного раза в час |
| NFR-06.02 | Резервные копии должны храниться в хранилище, отказ которого не приводит к одновременной потере рабочей БД и резервных копий |
| NFR-06.03 | Должны храниться последние 24 успешно созданные часовые резервные копии и последние 7 ежедневных резервных копий БД |
| NFR-06.04 | Система должна обеспечивать восстановление всех данных БД из выбранной доступной резервной копии |

---

## 5. Логирование

### NFR-07. Логирование ошибок

| **ID** | **Требование** |
| --- | --- |
| NFR-07.01 | Система должна фиксировать в backend-логах технические ошибки, возникшие при выполнении операций с записями, авторизации косметолога, обращении к БД и взаимодействии с внешними сервисами |
| NFR-07.02 | Каждая запись об ошибке в backend-логах должна содержать дату и время события, уровень логирования и описание ошибки |
| NFR-07.03 | При ошибке отправки SMS система должна зафиксировать в backend-логах идентификатор уведомления, идентификатор записи, SMS-провайдера, код ошибки и текст ошибки, полученные от SMS-провайдера |
| NFR-07.04 | Backend-логи не должны содержать пароль косметолога, refresh-токен, JWT-токен, а также полные значения номера телефона, email и токена доступа к записи |

---

## 6. Безопасность

### NFR-08. Авторизация и управление доступом

| **ID** | **Требование** |
| --- | --- |
| NFR-08.01 | Доступ к личному кабинету и функциям управления профилем, процедурами, расписанием и записями должен предоставляться только успешно авторизованному косметологу |
| NFR-08.02 | После выхода косметолога refresh token текущей сессии не должен приниматься системой для получения нового JWT, а cookie с refresh token должна быть удалена ответом backend-системы |
| NFR-08.03 | При вводе неправильного логина или пароля система должна отображать общее сообщение об ошибке без указания, какие именно данные введены неверно |
| NFR-08.04 | Все защищенные REST API-методы должны принимать токен авторизации в заголовке Authorization по схеме Bearer |
| NFR-08.05 | Система должна ограничивать количество запросов к защищенным REST API-методам от одного авторизованного пользователя до 20 запросов в минуту |
| NFR-08.06 | Система должна ограничивать количество запросов к публичным REST API-методам от одного IP-адреса до 60 запросов в минуту |
| NFR-08.07 | Система должна ограничивать количество запросов на создание записи от одного IP-адреса до 5 запросов в минуту |
| NFR-08.08 | Срок действия JWT косметолога должен составлять 15 минут с момента его выдачи |
| NFR-08.09 | Срок действия refresh token косметолога должен составлять 30 календарных дней с момента его выдачи |
| NFR-08.10 | Refresh token должен передаваться в cookie с атрибутами HttpOnly и Secure |

### NFR-09. Требования к паролю

| **ID** | **Требование** |
| --- | --- |
| NFR-09.01 | Система должна принимать пароль косметолога длиной от 15 до 64 символов включительно |
| NFR-09.02 | Пароль косметолога должен храниться в виде хеша, сформированного алгоритмом, предназначенным для хранения паролей, с уникальной солью |

### NFR-10. Защита персональных данных

| **ID** | **Требование** |
| --- | --- |
| NFR-10.01 | Доступ к персональным данным клиента через пользовательский интерфейс должен предоставляться только авторизованному косметологу |
| NFR-10.02 | Передача персональных данных клиента и данных, используемых для авторизации косметолога, должна выполняться только по защищенному соединению HTTPS |
| NFR-10.03 | База данных, используемая для хранения персональных данных клиентов, должна находиться на территории Российской Федерации |

## 7. Совместимость

### NFR-11. Поддержка устройств и браузеров

| **ID** | **Требование** |
| --- | --- |
| NFR-11.01 | Интерфейс публичной части сайта должен корректно отображаться на мобильных устройствах, планшетах и десктопах без горизонтальной прокрутки страницы, перекрытия элементов управления и обрезания текста, необходимого для выполнения пользовательского сценария |
| NFR-11.02 | Клиент должен иметь возможность полностью выполнять основные сценарии публичной части сайта на мобильном устройстве |
| NFR-11.03 | Размер области нажатия интерактивных элементов, используемых на мобильном устройстве, должен быть не менее 44 × 44 CSS-пикселей |
| NFR-11.04 | Основные пользовательские сценарии должны выполняться без ошибок, препятствующих завершению сценария, в текущей стабильной и предыдущей стабильной версиях браузеров Chrome, Safari, Firefox, Yandex и Edge |
