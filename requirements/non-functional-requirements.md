# Перечень нефункциональных требований

## 1. Удобство использования

### NFR-01. Понятность интерфейса

| **ID** | **Требование** | **Связанные требования и сценарии** |
|---|---|---|
| NFR-01.01 | Названия элементов интерфейса должны использовать термины предметной области, понятные клиенту и косметологу, и не должны содержать названия таблиц, полей БД, внутренних кодов статусов и названия API-параметров | `UC-01` |
| NFR-01.02 | Сообщение об ошибке должно содержать понятное пользователю описание причины, по которой операция не была выполнена | `FRQ-03.08`, `FRQ-05.07`, `FRQ-06.06` |
| NFR-01.03 | Если пользователь может самостоятельно устранить ошибку, сообщение должно содержать указание на необходимое действие | `FRQ-03.08`, `FRQ-05.07`, `FRQ-06.06` |

## 3. Доступность и устойчивость сервиса

### NFR-04. Доступность и устойчивость онлайн-записи

|---|---|---|

## 4. Целостность и сохранность данных

### NFR-05. Согласованность данных записи

| **ID** | **Требование** | **Связанные требования и сценарии** |
|---|---|---|
| NFR-05.01 | Операция создания записи должна завершаться либо сохранением записи и всех данных, создаваемых в рамках этой операции, либо отсутствием любых изменений | <code>FRQ&#8209;05.01–FRQ&#8209;05.03</code><br><code>BR&#8209;BOOKING&#8209;01</code> |
| NFR-05.02 | Операция отмены записи должна завершаться либо сохранением статуса <code>canceled</code> и даты и времени отмены, либо отсутствием любых изменений | <code>FRQ&#8209;10.06</code><br><code>FRQ&#8209;12.04</code><br><code>BR&#8209;CANCEL&#8209;01</code> |
| NFR-05.03 | Повторная отправка запроса на создание записи с теми же параметрами не должна создавать вторую активную запись на тот же временной интервал | <code>FRQ&#8209;02.16</code><br><code>FRQ&#8209;05.01</code><br><code>BR&#8209;SLOT&#8209;02–BR&#8209;SLOT&#8209;04</code> |

## 5. Логирование

### NFR-07. Логирование ошибок

| **ID** | **Требование** | **Связанные требования и сценарии** |
|---|---|---|
| NFR-07.01 | Система должна фиксировать в backend-логах ошибки, возникшие при выполнении операций с записями, авторизации, обращении к БД и взаимодействии с внешними сервисами | <code>FRQ&#8209;05.01</code><br><code>FRQ&#8209;06.06</code><br><code>FRQ&#8209;10.06</code><br><code>FRQ&#8209;11.11</code><br><code>FRQ&#8209;12.04</code> |
| NFR-07.02 | Каждая запись об ошибке в backend-логах должна содержать дату и время события, уровень логирования и описание ошибки | <code>FRQ&#8209;05.07</code><br><code>FRQ&#8209;11.11</code> |
| NFR-07.03 | При ошибке отправки SMS система должна зафиксировать в backend-логах идентификатор уведомления, идентификатор записи, SMS-провайдера, код ошибки и текст ошибки, полученные от SMS-провайдера | <code>FRQ&#8209;11.11</code> |
| NFR-07.04 | Backend-логи не должны содержать пароль косметолога, refresh-токен, JWT-токен, а также полные значения номера телефона, email и токена доступа к записи | <code>BR&#8209;BOOKING&#8209;05</code><br><code>BR&#8209;USER&#8209;06</code><br><code>FRQ&#8209;03.06</code><br><code>FRQ&#8209;12.01</code> |

## 6. Безопасность

### NFR-08. Авторизация и управление доступом

| **ID** | **Требование** | **Связанные требования и сценарии** |
|---|---|---|
| NFR-08.01 | Доступ к личному кабинету и функциям управления профилем, процедурами, расписанием и записями должен предоставляться только успешно авторизованному косметологу | <code>BR&#8209;USER&#8209;06</code><br><code>UC&#8209;02</code><br><code>FRQ&#8209;07.01</code><br><code>FRQ&#8209;08.01</code><br><code>FRQ&#8209;09.01</code><br><code>FRQ&#8209;10.01</code> |
| NFR-08.02 | После выхода косметолога refresh token текущей сессии не должен приниматься системой для получения нового JWT, а cookie с refresh token должна быть удалена ответом backend-системы | <code>FRQ&#8209;06.08</code> |
| NFR-08.03 | При вводе неправильного логина или пароля система должна отображать общее сообщение об ошибке без указания, какие именно данные введены неверно | <code>FRQ&#8209;06.06</code> |
| NFR-08.04 | Все защищенные REST API-методы должны принимать токен авторизации в заголовке <code>Authorization</code> по схеме <code>Bearer</code> | <code>FRQ&#8209;06.04</code><br><code>FRQ&#8209;06.05</code> |
| NFR-08.05 | Система должна ограничивать количество запросов к защищенным REST API-методам от одного авторизованного пользователя до 20 запросов в минуту | <code>FRQ&#8209;07.01</code><br><code>FRQ&#8209;08.01</code><br><code>FRQ&#8209;09.01</code><br><code>FRQ&#8209;10.01</code> |
| NFR-08.06 | Срок действия JWT косметолога должен составлять 15 минут с момента его выдачи | <code>FRQ&#8209;06.04</code><br><code>FRQ&#8209;06.09</code> |
| NFR-08.07 | Срок действия refresh token косметолога должен составлять 30 календарных дней с момента его выдачи | <code>FRQ&#8209;06.04</code><br><code>FRQ&#8209;06.09</code> |
| NFR-08.08 | Refresh token должен передаваться в cookie с атрибутами <code>HttpOnly</code> и <code>Secure</code> | <code>FRQ&#8209;06.04</code><br><code>FRQ&#8209;06.09</code> |

### NFR-09. Требования к паролю

| **ID** | **Требование** | **Связанные требования и сценарии** |
|---|---|---|
| NFR-09.01 | Система должна принимать пароль косметолога длиной от 8 до 64 символов включительно | <code>FRQ&#8209;06.02–FRQ&#8209;06.04</code> |
| NFR-09.02 | Пароль косметолога должен храниться в виде хеша, сформированного алгоритмом, предназначенным для хранения паролей, с уникальной солью | <code>BR&#8209;USER&#8209;06</code> |

### NFR-10. Защита персональных данных

| **ID** | **Требование** | **Связанные требования и сценарии** |
|---|---|---|
| NFR-10.01 | Доступ к персональным данным клиента должен предоставляться только авторизованному косметологу либо пользователю, предъявившему действительный токен доступа к соответствующей записи | <code>UC&#8209;02</code><br><code>UC&#8209;05</code><br><code>UC&#8209;07</code><br><code>BR&#8209;BOOKING&#8209;05–BR&#8209;BOOKING&#8209;06</code> |
| NFR-10.02 | Передача персональных данных клиента и данных, используемых для авторизации косметолога, должна выполняться только по защищенному соединению HTTPS | <code>UC&#8209;01–UC&#8209;02</code><br><code>UC&#8209;07</code> |
| NFR-10.03 | База данных, используемая для хранения персональных данных клиентов, должна находиться на территории Российской Федерации | <code>UC&#8209;01</code><br><code>FRQ&#8209;03.01–FRQ&#8209;03.07</code> |

|---|---|---|

| NFR-11.03 | Размер области нажатия интерактивных элементов, используемых в основном сценарии онлайн-записи на мобильном устройстве, должен быть не менее 44 × 44 CSS-пикселей | <code>UC&#8209;01</code> |
| NFR-11.04 | Основные пользовательские сценарии должны выполняться без ошибок, препятствующих завершению сценария, в текущей стабильной и предыдущей стабильной версиях браузеров Chrome, Safari, Firefox и Edge | <code>UC&#8209;01–UC&#8209;09</code> |
