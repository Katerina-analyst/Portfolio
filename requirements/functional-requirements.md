# Перечень функциональных требований

## 1. Онлайн-запись клиента на процедуру

### FRQ-01. Просмотр и выбор категорий и процедур
**Назначение:** предоставить клиенту возможность выбрать категорию и процедуру для онлайн-записи

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-01.01 | Система должна отображать клиенту список категорий процедур |
| FRQ-01.02 | Система должна позволять клиенту выбрать категорию процедур |
| FRQ-01.03 | Система должна отображать список процедур выбранной категории только после выбора категории процедур |
| FRQ-01.04 | Система должна отображать только процедуры, доступные для онлайн-записи |
| FRQ-01.05 | Система должна отображать клиенту название, краткое описание, стоимость и длительность процедуры |
### FRQ-02. Выбор даты и времени

**Назначение:** предоставить клиенту возможность выбрать дату и время визита

| **Идентификатор** | **Описание** |
| ----------------- | ------------ |
| FRQ-02.01 | Система должна определять будущие доступные даты после выбора процедуры |
| FRQ-02.02 | Система должна отображать клиенту доступные даты для выбранной процедуры |
| FRQ-02.03 | Система должна позволять клиенту выбрать доступную дату визита |
| FRQ-02.04 | После выбора даты система должна формировать свободные слоты для выбранной процедуры в соответствии с алгоритмом **ALG-01 «Формирование свободных слотов»** |
| FRQ-02.05 | Система должна отображать клиенту сформированный список свободных слотов на выбранную дату |
| FRQ-02.06 | Система должна позволять клиенту выбрать свободный слот |
| FRQ-02.07 | Перед созданием записи система должна повторно проверить доступность выбранного слота |
| FRQ-02.08 | Если выбранный слот стал недоступен до создания записи, система должна сохранить ранее введенные значения полей формы и предложить клиенту выбрать другой свободный слот |

### FRQ-03. Ввод контактных данных и согласия
**Назначение:** предоставить клиенту возможность ввести контактные данные и дать согласие на обработку персональных данных для дальнейшего создания записи

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-03.01 | Система должна отображать поля имени и номера телефона в форме онлайн-записи |
| FRQ-03.02 | Система должна позволять клиенту вводить и изменять имя и номер телефона в любом порядке до подтверждения записи |
| FRQ-03.03 | Система не должна требовать регистрации клиента для создания записи |
| FRQ-03.04 | Система должна проверять заполнение всех обязательных данных формы онлайн-записи |
| FRQ-03.05 | Система должна проверять корректность имени клиента |
| FRQ-03.06 | Система должна проверять корректность номера телефона клиента до создания записи |
| FRQ-03.07 | Система должна приводить корректный номер телефона клиента к единому формату перед поиском клиента и сохранением данных |
| FRQ-03.08 | Если номер телефона не соответствует установленному формату, система не должна создавать запись и должна сообщить клиенту об ошибке |
| FRQ-03.09 | Система должна отображать клиенту чекбокс согласия на обработку персональных данных |
| FRQ-03.10 | Система должна фиксировать согласие клиента на обработку персональных данных |
| FRQ-03.11 | Система должна визуально обозначать обязательные поля формы онлайн-записи |
| FRQ-03.12 | При ошибке валидации система должна сохранять значения полей формы, успешно прошедших валидацию |
| FRQ-03.13 | Система должна отображать рядом с чекбоксом согласия ссылку на документ об обработке персональных данных |

### FRQ-04. Подтверждение записи
**Назначение:** предоставить клиенту возможность проверить выбранные данные и подтвердить запись на процедуру

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-04.01 | Система должна позволять клиенту подтвердить запись после выбора категории, процедуры, доступной даты и свободного слота, корректного заполнения имени и номера телефона и предоставления согласия на обработку персональных данных |
| FRQ-04.02 | Система должна позволять клиенту изменять параметры записи до ее подтверждения |
| FRQ-04.03 | Система должна позволять клиенту прервать процесс онлайн-записи до подтверждения |
| FRQ-04.04 | Система не должна позволять клиенту подтвердить запись, если обязательные данные отсутствуют или заполнены некорректно, не выбран свободный слот или не предоставлено согласие на обработку персональных данных |
| FRQ-04.05 | Система должна отображать кнопку подтверждения записи в неактивном состоянии, если не выполнено хотя бы одно из условий подтверждения записи, и в активном состоянии после выполнения всех условий |
| FRQ-04.06 | После отправки формы онлайн-записи система должна заблокировать повторное подтверждение и отображать клиенту индикатор ожидания до получения результата операции или сообщения об ошибке |

### FRQ-05. Создание записи
**Назначение:** обеспечить создание записи клиента на процедуру, чтобы учитывать ее при отправке уведомлений и при последующем формировании свободных дат и слотов

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-05.01 | Система должна создавать запись после подтверждения клиентом формы онлайн-записи |
| FRQ-05.02 | Система должна связывать созданную запись с клиентом, процедурой и днем расписания, а также сохранять время начала и окончания визита |
| FRQ-05.03 | Система должна сформировать и связать с созданной записью уникальный токен доступа |
| FRQ-05.04 | После успешного создания записи система должна отображать клиенту подтверждение успешной записи |
| FRQ-05.05 | После создания записи система должна формировать уникальную ссылку для просмотра и отмены записи |
| FRQ-05.06 | После создания записи система должна инициировать отправку уведомлений клиенту и косметологу |
| FRQ-05.07 | Если запись не удалось создать, система должна сообщить клиенту об ошибке |
| FRQ-05.08 | При создании записи система должна сохранять стоимость процедуры, действующую на момент создания записи |
| FRQ-05.09 | Перед созданием записи система должна выполнить поиск клиента по номеру телефона |
| FRQ-05.10 | Если клиент с указанным номером телефона найден, система должна связать запись с существующим клиентом; если клиент не найден, система должна создать нового клиента |
| FRQ-05.11 | Система должна создавать запись только в том случае, если выбранный временной интервал остается доступным непосредственно в момент сохранения записи |
| FRQ-05.12 | Если выбранный временной интервал уже занят другой активной записью, система не должна создавать запись и должна предложить клиенту выбрать другой свободный слот |

## 2. Авторизация косметолога

### FRQ-06. Авторизация косметолога
**Назначение:** предоставить косметологу возможность авторизоваться и получить доступ к личному кабинету

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-06.01 | Система должна отображать форму авторизации при переходе косметолога на страницу входа |
| FRQ-06.02 | Система должна позволять косметологу ввести логин и пароль |
| FRQ-06.03 | Система должна проверять введенные логин и пароль на соответствие данным учетной записи косметолога |
| FRQ-06.04 | Если логин и пароль корректны, система должна авторизовать косметолога |
| FRQ-06.05 | После успешной авторизации система должна предоставить косметологу доступ к личному кабинету |
| FRQ-06.06 | Если логин или пароль некорректны, система должна сообщить косметологу, что данные для входа неверны |
| FRQ-06.07 | После 3 последовательных неуспешных попыток входа система должна заблокировать авторизацию косметолога на 60 минут и сообщить время, после которого следующая попытка входа будет доступна |
| FRQ-06.08 | Система должна позволять косметологу выйти из личного кабинета |
| FRQ-06.09 | При наличии действительного refresh token система должна получать новый JWT без повторного ввода косметологом логина и пароля |
| FRQ-06.10 | Если refresh token отсутствует, недействителен или срок его действия истек, система должна потребовать повторную авторизацию косметолога |

## 4. Управление процедурами

### FRQ-08. Управление процедурами
**Назначение:** предоставить косметологу возможность управлять процедурами: добавлять новые процедуры, редактировать данные существующих процедур и изменять их доступность для онлайн-записи

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-08.01 | Система должна позволять косметологу создавать процедуру |
| FRQ-08.02 | Система должна позволять косметологу при создании и редактировании процедуры указывать название, описание, стоимость, длительность и статус |
| FRQ-08.03 | Система должна позволять косметологу выбирать и изменять категорию процедуры только из преднастроенного справочника |
| FRQ-08.04 | Система должна предоставлять клиенту возможность онлайн-записи на процедуры со статусом `available` |
| FRQ-08.05 | Система не должна предоставлять клиенту возможность онлайн-записи на процедуры со статусом `unavailable` |
| FRQ-08.06 | Система должна позволять косметологу просматривать список созданных процедур |
| FRQ-08.07 | Система не должна предоставлять косметологу возможность создавать новые категории процедур в MVP |

## 5. Настройка расписания

### FRQ-09. Управление расписанием
**Назначение:** предоставить косметологу возможность настраивать рабочие дни, рабочее время и недоступные периоды, чтобы система могла корректно формировать доступные даты и свободные слоты для онлайн-записи

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-09.01 | Система должна позволять косметологу создавать расписание на выбранный период |
| FRQ-09.02 | При создании расписания система должна проверять, что его календарный период не пересекается с календарными периодами других расписаний косметолога |
| FRQ-09.03 | Система должна позволять косметологу изменять признак рабочего дня |
| FRQ-09.04 | Для рабочего дня система должна требовать указания времени начала и окончания работы |
| FRQ-09.05 | Для нерабочего дня система не должна учитывать указанное время начала и окончания работы |
| FRQ-09.06 | Система должна позволять косметологу создавать недоступный период внутри рабочего дня |
| FRQ-09.07 | Система должна позволять косметологу изменять время начала, время окончания и причину недоступного периода |
| FRQ-09.08 | Система должна проверять, что недоступный период полностью находится внутри рабочего интервала дня расписания |
| FRQ-09.09 | Система должна проверять, что недоступные периоды одного дня расписания не пересекаются между собой или с активными записями |
| FRQ-09.10 | Система должна позволять косметологу отменить ранее созданный недоступный период |
| FRQ-09.11 | Система должна учитывать рабочий интервал дня расписания, недоступные периоды и активные записи при формировании свободных слотов |
| FRQ-09.12 | Система должна позволять косметологу изменять время начала и окончания рабочего дня |
| FRQ-09.13 | Система не должна позволять косметологу сделать день нерабочим или изменить рабочий интервал, если есть активная запись в пределах рабочего интервала |

## 6. Управление записями косметологом

### FRQ-10. Просмотр и управление статусами записей косметологом
**Назначение:** предоставить косметологу возможность просматривать записи клиентов, отменять активные записи при необходимости и отмечать неявки клиентов

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-10.01 | Система должна позволять косметологу просматривать календарь записей |
| FRQ-10.02 | Система должна позволять косметологу выбирать период просмотра календаря записей |
| FRQ-10.03 | Система должна позволять косметологу просматривать карточку записи |
| FRQ-10.04 | Система должна отображать в карточке записи процедуру, длительность, фиксированную стоимость, дату, время визита и контактные данные клиента |
| FRQ-10.05 | Система должна позволять косметологу отменить активную запись до наступления времени начала записи |
| FRQ-10.06 | При отмене записи косметологом система должна изменить статус записи на `canceled` |
| FRQ-10.07 | После успешной отмены записи система должна отобразить косметологу подтверждение отмены |
| FRQ-10.08 | При отмене записи косметологом система должна инициировать отправку уведомления клиенту |
| FRQ-10.09 | Перед отменой записи система должна запросить у косметолога подтверждение операции |
| FRQ-10.10 | При отмене записи косметологом система должна зафиксировать дату и время отмены |
| FRQ-10.11 | После отмены записи система должна учитывать освободившийся временной интервал при последующем формировании свободных слотов |
| FRQ-10.12 | После наступления даты и времени окончания приема система должна автоматически изменить статус записи с `created` на `completed` |
| FRQ-10.13 | Автоматическое изменение статуса на `completed` должно выполняться только для записей со статусом `created` |
| FRQ-10.14 | Система должна позволять косметологу установить для записи статус `no_show`, если клиент не явился на прием |
| FRQ-10.15 | Установка статуса `no_show` должна быть доступна после наступления даты и времени начала приема |
| FRQ-10.16 | Система должна позволять косметологу изменить статус записи с `created` или `completed` на `no_show` |
| FRQ-10.17 | Перед установкой статуса `no_show` система должна запросить у косметолога подтверждение операции |
| FRQ-10.18 | После успешной установки статуса `no_show` система должна отобразить косметологу подтверждение изменения статуса |
| FRQ-10.19 | Система должна позволять косметологу фильтровать записи по статусу |

## 7. Уведомления

### FRQ-11. Создание и отправка уведомлений
**Назначение:** обеспечить создание и отправку SMS-уведомлений клиенту и косметологу при создании записи, отмене записи и наступлении времени напоминания о визите

| **Идентификатор** | **Описание** |
|---|---|
| FRQ-11.01 | После создания записи система должна создавать уведомление клиенту |
| FRQ-11.02 | После создания записи система должна создавать уведомление косметологу |
| FRQ-11.03 | После отмены записи косметологом система должна создавать уведомление клиенту |
| FRQ-11.04 | После отмены записи клиентом система должна создавать уведомление косметологу |
| FRQ-11.05 | За 24 часа до времени начала активной записи система должна создавать напоминание клиенту |
| FRQ-11.06 | Система должна присваивать новому уведомлению статус `created` |
| FRQ-11.07 | Система должна инициировать отправку созданного уведомления |
| FRQ-11.08 | После попытки отправки система должна изменять статус уведомления в соответствии с результатом отправки |
| FRQ-11.09 | Система должна фиксировать дату и время создания уведомления |
| FRQ-11.10 | При успешной отправке уведомления система должна фиксировать дату и время его отправки |
| FRQ-11.11 | Если уведомление не отправлено, система должна присвоить уведомлению статус `error` и зафиксировать сведения об ошибке в журнале |
| FRQ-11.12 | Ошибка отправки уведомления не должна изменять статус созданной или отмененной записи |
| FRQ-11.13 | Система должна отправлять уведомление клиенту и косметологу по сохраненному номеру телефона |

---

## 8. Отмена записи клиентом

### FRQ-12. Просмотр и отмена записи клиентом по ссылке
**Назначение:** предоставить клиенту возможность просмотреть данные своей записи по ссылке и отменить активную запись без регистрации

| **Идентификатор** | **Описание** |
|---|---|
