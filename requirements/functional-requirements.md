# Функциональные требования

## 1. Онлайн-запись клиента на процедуру

### FRQ-01. Просмотр и выбор категорий и процедур
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-01.01 | Система должна отображать клиенту список категорий процедур |
| FRQ-01.02 | Система должна позволять клиенту выбрать категорию процедур |
| FRQ-01.03 | Система должна отображать список процедур выбранной категории |
| FRQ-01.04 | Система должна отображать только процедуры, доступные для онлайн-записи |
| FRQ-01.05 | Система должна отображать клиенту название, краткое описание, стоимость и длительность процедуры |

### FRQ-02. Выбор даты и времени
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-02.01 | Система должна определять будущие доступные даты после выбора процедуры |
| FRQ-02.02 | Система должна отображать клиенту доступные даты для выбранной процедуры |
| FRQ-02.03 | Система должна позволять клиенту выбрать доступную дату визита |
| FRQ-02.04 | После выбора даты система должна определить день расписания на выбранную дату |
| FRQ-02.05 | Если день расписания не найден или является нерабочим, система должна возвращать пустой список свободных слотов |
| FRQ-02.06 | Для рабочего дня система должна определить свободные временные интервалы с учетом рабочего интервала, недоступных периодов и активных записей |
| FRQ-02.07 | Система не должна формировать слот, если длительность свободного временного интервала меньше длительности выбранной процедуры |
| FRQ-02.08 | Продолжительность каждого слота должна соответствовать продолжительности выбранной процедуры |
| FRQ-02.09 | Первый слот должен начинаться со времени начала свободного временного интервала |
| FRQ-02.10 | Время окончания слота должно рассчитываться как сумма времени начала слота и продолжительности выбранной процедуры |
| FRQ-02.11 | Каждый следующий слот должен начинаться со времени окончания предыдущего слота |
| FRQ-02.12 | Система должна формировать только слоты, полностью находящиеся внутри свободного временного интервала |
| FRQ-02.13 | Система должна объединять слоты из всех свободных временных интервалов и сортировать их по времени начала по возрастанию |
| FRQ-02.14 | Система должна отображать клиенту сформированный список свободных слотов на выбранную дату |
| FRQ-02.15 | Система должна позволять клиенту выбрать свободный слот |
| FRQ-02.16 | Перед созданием записи система должна повторно проверить доступность выбранного слота |
| FRQ-02.17 | Если выбранный слот стал недоступен до создания записи, система должна сохранить ранее введенные значения полей формы в интерфейсе и предложить клиенту выбрать другой свободный слот |

### FRQ-03. Ввод контактных данных и согласия
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-03.01 | Система должна отображать поля имени и номера телефона в форме онлайн-записи |
| FRQ-03.02 | Система должна позволять клиенту ввести имя и номер телефона |
| FRQ-03.03 | Система не должна требовать регистрации клиента для создания записи |
| FRQ-03.04 | Система должна проверять заполнение всех обязательных данных формы онлайн-записи |
| FRQ-03.05 | Система должна проверять корректность имени клиента |
| FRQ-03.06 | Система должна проверять корректность номера телефона клиента до создания записи |
| FRQ-03.07 | Система должна приводить корректный номер телефона клиента к единому формату перед поиском клиента и сохранением данных |
| FRQ-03.08 | Если номер телефона не соответствует установленному формату, система не должна создавать запись и должна сообщить клиенту об ошибке |
| FRQ-03.09 | Система должна отображать клиенту чекбокс согласия на обработку персональных данных |
| FRQ-03.10 | Система должна фиксировать согласие клиента на обработку персональных данных |
| FRQ-03.11 | Система должна визуально обозначать обязательные поля формы онлайн-записи |
| FRQ-03.12 | При ошибке валидации система должна сохранять значения полей формы, успешно прошедших валидацию |
| FRQ-03.13 | Система должна отображать рядом с чекбоксом согласия ссылку на документ об обработке персональных данных |

### FRQ-04. Подтверждение записи
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-04.01 | Система должна позволять клиенту подтвердить запись после выбора категории, процедуры, доступной даты и свободного слота, корректного заполнения имени и номера телефона и предоставления согласия на обработку персональных данных |
| FRQ-04.02 | Система должна позволять клиенту изменять параметры записи до ее подтверждения |
| FRQ-04.03 | Система должна позволять клиенту прервать процесс онлайн-записи до подтверждения |
| FRQ-04.04 | Система не должна позволять клиенту подтвердить запись, если обязательные данные отсутствуют или заполнены некорректно, не выбран свободный слот или не предоставлено согласие на обработку персональных данных |
| FRQ-04.05 | Система должна отображать кнопку подтверждения записи в неактивном состоянии, если не выполнено хотя бы одно из условий подтверждения записи, и в активном состоянии после выполнения всех условий |
| FRQ-04.06 | После отправки формы онлайн-записи система должна заблокировать повторное подтверждение и отображать клиенту индикатор ожидания до получения результата операции или сообщения об ошибке |

### FRQ-05. Создание записи
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-05.01 | Система должна создавать запись после подтверждения клиентом формы онлайн-записи |
| FRQ-05.02 | Система должна связывать созданную запись с клиентом, процедурой и днем расписания, а также сохранять время начала и окончания визита |
| FRQ-05.03 | Система должна сформировать и связать с созданной записью уникальный токен доступа |
| FRQ-05.04 | После успешного создания записи система должна отображать клиенту подтверждение успешной записи |
| FRQ-05.05 | После создания записи система должна формировать уникальную ссылку для просмотра и отмены записи |
| FRQ-05.06 | После создания записи система должна инициировать отправку уведомлений клиенту и мастеру |
| FRQ-05.07 | Если запись не удалось создать, система должна сообщить клиенту об ошибке |
| FRQ-05.08 | При создании записи система должна сохранять стоимость процедуры, действующую на момент создания записи |
| FRQ-05.09 | Перед созданием записи система должна выполнить поиск клиента по номеру телефона |
| FRQ-05.10 | Если клиент с указанным номером телефона найден, система должна связать запись с существующим клиентом; если клиент не найден, система должна создать нового клиента |
| FRQ-05.11 | Система должна создавать запись только в том случае, если выбранный временной интервал остается доступным непосредственно в момент сохранения записи |
| FRQ-05.12 | Если выбранный временной интервал уже занят другой активной записью, система не должна создавать запись и должна предложить клиенту выбрать другой свободный слот |

## 2. Авторизация мастера

### FRQ-06. Вход в личный кабинет мастера
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-06.01 | Система должна отображать форму авторизации при переходе мастера на страницу входа |
| FRQ-06.02 | Система должна позволять мастеру ввести логин и пароль |
| FRQ-06.03 | Система должна проверять введенные логин и пароль на соответствие данным учетной записи мастера |
| FRQ-06.04 | Если логин и пароль корректны, система должна авторизовать мастера |
| FRQ-06.05 | После успешной авторизации система должна предоставить мастеру доступ к личному кабинету |
| FRQ-06.06 | Если логин или пароль некорректны, система должна сообщить мастеру, что данные для входа неверны |
| FRQ-06.07 | После 3 последовательных неуспешных попыток входа система должна заблокировать авторизацию мастера на 60 минут и сообщить время, после которого следующая попытка входа будет доступна |
| FRQ-06.08 | Система должна позволять мастеру выйти из личного кабинета |
| FRQ-06.09 | При наличии действительного refresh token система должна получать новый JWT без повторного ввода мастером логина и пароля |
| FRQ-06.10 | Если refresh token отсутствует, недействителен или срок его действия истек, система должна потребовать повторную авторизацию мастера |

## 4. Управление процедурами

### FRQ-08. Управление процедурами
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-08.01 | Система должна позволять мастеру создавать процедуру |
| FRQ-08.02 | Система должна позволять мастеру при создании и редактировании процедуры указывать название, описание, стоимость, длительность и статус |

| FRQ-08.07 | Система не должна предоставлять мастеру возможность создавать новые категории процедур в MVP |

## 5. Настройка расписания

### FRQ-09. Управление расписанием
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-09.01 | Система должна позволять мастеру создавать расписание на выбранный период |
| FRQ-09.02 | При создании расписания система должна проверять, что его календарный период не пересекается с календарными периодами других расписаний мастера |
| FRQ-09.03 | Система должна позволять мастеру изменять признак рабочего дня |
| FRQ-09.04 | Для рабочего дня система должна требовать указания времени начала и окончания работы |
| FRQ-09.05 | Для нерабочего дня система не должна учитывать указанное время начала и окончания работы |
| FRQ-09.06 | Система должна позволять мастеру создавать недоступный период внутри рабочего дня |
| FRQ-09.07 | Система должна позволять мастеру изменять время начала, время окончания и причину недоступного периода |
| FRQ-09.08 | Система должна проверять, что недоступный период полностью находится внутри рабочего интервала дня расписания |
| FRQ-09.09 | Система должна проверять, что недоступные периоды одного дня расписания не пересекаются между собой или с активными записями |
| FRQ-09.10 | Система должна позволять мастеру отменить ранее созданный недоступный период |
| FRQ-09.11 | Система должна учитывать рабочий интервал дня расписания, недоступные периоды и активные записи при формировании свободных слотов |
| FRQ-09.12 | Система должна позволять мастеру изменять время начала и окончания рабочего дня |
| FRQ-09.13 | Система не должна позволять мастеру сделать день нерабочим или изменить рабочий интервал, если есть активная запись в пределах рабочего интервала |

| FRQ-10.11 | После отмены записи система должна учитывать освободившийся временной интервал при последующем формировании свободных слотов |

## 7. Уведомления

### FRQ-11. Создание и отправка уведомлений
| **Идентификатор** | **Описание** |
|---|---|
| FRQ-11.01 | После создания записи система должна создавать уведомление клиенту |
| FRQ-11.02 | После создания записи система должна создавать уведомление мастеру |
| FRQ-11.03 | После отмены записи мастером система должна создавать уведомление клиенту |
| FRQ-11.04 | После отмены записи клиентом система должна создавать уведомление мастеру |
| FRQ-11.05 | За 24 часа до времени начала активной записи система должна создавать напоминание клиенту |
| FRQ-11.06 | Система должна присваивать новому уведомлению статус `created` |
| FRQ-11.07 | Система должна инициировать отправку созданного уведомления |
| FRQ-11.08 | После попытки отправки система должна изменять статус уведомления в соответствии с результатом отправки |
| FRQ-11.09 | Система должна фиксировать дату и время создания уведомления |
| FRQ-11.10 | При успешной отправке уведомления система должна фиксировать дату и время его отправки |
| FRQ-11.11 | Если уведомление не отправлено, система должна присвоить уведомлению статус `error` и зафиксировать сведения об ошибке в журнале |
| FRQ-11.12 | Ошибка отправки уведомления не должна изменять статус созданной или отмененной записи |
| FRQ-11.13 | Система должна отправлять уведомление клиенту и мастеру по сохраненному номеру телефона |
