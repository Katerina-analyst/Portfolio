# Нефункциональные требования

## 1. Удобство использования

### NFRQ-01. Понятность интерфейса

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-01.01 | Интерфейс должен позволять клиенту завершить онлайн-запись без дополнительного обучения |
| NFRQ-01.02 | Основной сценарий онлайн-записи должен быть доступен с главной страницы и из ключевых разделов сайта, связанных с выбором процедуры |
| NFRQ-01.03 | Текст кнопок, ссылок и полей ввода должен быть однозначным, соответствовать косметологическому домену и не содержать технических терминов |
| NFRQ-01.04 | В случае некорректного ввода данных система должна показывать сообщение об ошибке рядом с полем, поясняющее причину и способ исправления |
| NFRQ-01.05 | После успешной записи система должна показать клиенту подтверждение с параметрами записи и информацией о способе просмотра или отмены записи |

### NFRQ-02. Удобство процесса онлайн-записи

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-02.01 | Форма онлайн-записи должна содержать только поля и элементы выбора, необходимые для записи на одну процедуру |
| NFRQ-02.02 | Клиент должен понимать, какие данные нужно заполнить для завершения онлайн-записи |
| NFRQ-02.03 | Система должна позволять клиенту изменить выбранное направление, процедуру, дату, время и контактные данные до подтверждения записи |
| NFRQ-02.04 | Обязательные поля формы записи должны быть явно обозначены |
| NFRQ-02.05 | При ошибке валидации система не должна очищать корректно заполненные поля формы |
| NFRQ-02.06 | Если выбранный слот стал недоступен, система должна сохранить введенные контактные данные и предложить выбрать другой свободный слот |

## 2. Производительность

### NFRQ-03. Скорость загрузки и отклика

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-03.01 | Основные страницы сайта должны загружаться не дольше 3 секунд при стабильном интернет-соединении на стандартном пользовательском устройстве |
| NFRQ-03.02 | После выбора направления, процедуры и даты система должна выполнить запрос на формирование доступных слотов и отобразить таблицу доступных вариантов в течение 3 секунд |
| NFRQ-03.03 | Формирование списка свободных слотов должно занимать не более 5 секунд при обычной пользовательской нагрузке MVP |
| NFRQ-03.04 | Подтверждение записи должно завершаться не более чем за 2 секунды после отправки данных клиентом |
| NFRQ-03.05 | При задержке ответа сервиса более 2 секунд система должна отображать пользователю индикатор ожидания |
| NFRQ-03.06 | Система должна показывать понятное уведомление о проблеме соединения или сетевой ошибке и предлагать клиенту повторить действие позже |
| NFRQ-03.07 | Онлайн-запись должна быть доступна пользователю вне зависимости от рабочего времени мастера, за исключением технических перерывов |

## 3. Надежность

### NFRQ-04. Корректность бронирования

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-04.01 | Система должна предотвращать создание двух активных записей на один и тот же временной слот |
| NFRQ-04.02 | Система должна повторно проверять доступность выбранного слота перед подтверждением записи |
| NFRQ-04.03 | Если выбранный слот стал недоступен до подтверждения записи, система должна сообщить об этом клиенту и предложить выбрать другой свободный слот без повторного ввода контактных данных |
| NFRQ-04.04 | После успешного создания записи система должна изменить статус выбранного слота на недоступный и обеспечить согласованность данных между расписанием и записями |
| NFRQ-04.05 | После отмены записи система должна освобождать слот для повторного бронирования, если это не противоречит бизнес-правилам, и фиксировать статус записи как отмененный |

### NFRQ-05. Обработка ошибок

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-05.01 | Система должна отображать клиенту понятное сообщение при технической ошибке, препятствующей завершению операции |
| NFRQ-05.02 | Система не должна создавать запись при ошибке проверки обязательных данных |
| NFRQ-05.03 | Система не должна создавать запись при ошибке проверки доступности слота |
| NFRQ-05.04 | Операции создания и отмены записи должны выполняться атомарно: при ошибке система должна откатывать частичные изменения |
| NFRQ-05.05 | Система должна исключать потерю уже созданной записи при обновлении страницы пользователем после подтверждения |
| NFRQ-05.06 | При ошибке система должна сохранять введенные данные клиента, если это технически возможно, и позволять повторить операцию без повторного заполнения формы |
| NFRQ-05.07 | Система должна вести простое логирование ошибок и критичных событий, чтобы можно было понять причину сбоя |

### NFRQ-06. Восстановление после сбоев

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-06.01 | Система должна сохранять целостность данных после сбоя, исключая рассогласование между слотами и записями |
| NFRQ-06.02 | Для данных о записях должны быть предусмотрены резервное копирование и возможность восстановления |

## 4. Безопасность

### NFRQ-07. Авторизация и управление доступом

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-07.01 | Личный кабинет мастера должен быть доступен только после успешной авторизации |
| NFRQ-07.02 | Система должна ограничивать доступ неавторизованных пользователей к функциям управления процедурами, расписанием и записями |
| NFRQ-07.03 | Система должна завершать сессию мастера после выхода из личного кабинета или по истечении времени бездействия |
| NFRQ-07.04 | При неправильном логине или пароле система должна показывать общее сообщение об ошибке, не раскрывая, что именно было введено неверно |
| NFRQ-07.05 | Система должна фиксировать попытки входа и временно блокировать доступ после 5 неудачных попыток в течение 10 минут |

### NFRQ-08. Требования к логину и паролю

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-08.01 | Пароль мастера должен быть длиной не менее 8 символов |
| NFRQ-08.02 | Система должна поддерживать использование длинных парольных фраз |
| NFRQ-08.03 | Пароль мастера должен храниться только в виде защищенного хеша |
| NFRQ-08.04 | Система должна ограничивать частоту неуспешных попыток входа |
| NFRQ-08.05 | Запрещено использовать подсказки к паролю и проверочные вопросы |

### NFRQ-09. Защита персональных данных

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-09.01 | Персональные данные клиента должны использоваться только для создания, сопровождения и отмены записи, а также для отправки уведомлений |
| NFRQ-09.02 | Система должна предоставлять мастеру доступ только к контактным данным клиентов, записанных к этому мастеру |
| NFRQ-09.03 | Система не должна отображать персональные данные клиентов в публичной части сайта |
| NFRQ-09.04 | Все персональные данные должны передаваться по защищенному соединению (HTTPS/TLS) |
| NFRQ-09.05 | Система должна хранить только данные, необходимые для выполнения сценария онлайн-записи, в течение срока, установленного политикой обработки персональных данных |
| NFRQ-09.06 | Система должна предоставить клиенту возможность ознакомиться с описанием политики обработки персональных данных: какие данные собираются, кем и как они будут обрабатываться, и каким образом будет обеспечена их защита |
| NFRQ-09.07 | Система не должна пропускать отправку формы онлайн-записи без подтверждения согласия на обработку персональных данных; такое согласие должно быть зафиксировано |
| NFRQ-09.08 | Система должна фиксировать критичные действия с записями и персональными данными клиента для последующего анализа инцидентов |
| NFRQ-09.09 | В рамках MVP данные клиентов должны храниться на серверах, расположенных на территории Российской Федерации |

## 5. Совместимость

### NFRQ-10. Поддержка устройств и браузеров

| **ID** | **Требование** |
| ------ | -------------- |
| NFRQ-10.01 | Интерфейс должен быть адаптивным и корректно отображаться на ключевых ширинах экранов (мобильные, планшеты, десктоп) |
| NFRQ-10.02 | Основной сценарий онлайн-записи должен быть доступен и удобен для использования на мобильных устройствах |
| NFRQ-10.03 | Элементы интерфейса должны быть удобны для нажатия на сенсорных экранах (минимальный размер цели касания) |
| NFRQ-10.04 | Система должна корректно работать в текущей стабильной и предыдущей версии браузеров Chrome, Safari, Firefox и Edge на момент релиза |
| NFRQ-10.05 | Система должна корректно работать на актуальных версиях популярных ОС: Windows, macOS, iOS и Android |
| NFRQ-10.06 | Система должна поддерживать корректную работу на компьютерах, ноутбуках, планшетах и смартфонах |
| NFRQ-10.07 | В рамках MVP интерфейс должен соответствовать базовым требованиям доступности |
