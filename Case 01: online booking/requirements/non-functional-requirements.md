# Нефункциональные требования

## 1. Удобство использования

### NFR-01. Понятность интерфейса

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-01.01 | Клиент должен иметь возможность завершить основной сценарий онлайн-записи без обращения к инструкции или помощи мастера |
| NFR-01.02 | Названия кнопок, ссылок и полей ввода должны описывать действие или вводимые данные без технических терминов |
| NFR-01.03 | Текст ошибок должен отображаться рядом с полем, к которому относится ошибка |
| NFR-01.04 | Текст ошибки должен содержать причину ошибки и способ ее исправления |
| NFR-01.05 | После успешной записи клиент должен видеть ключевые параметры записи в одном блоке подтверждения: процедуру, дату, время и стоимость |

### NFR-02. Удобство формы онлайн-записи

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-02.01 | Форма онлайн-записи должна содержать только поля и элементы выбора, необходимые для записи на одну процедуру |
| NFR-02.02 | Обязательные поля формы записи должны быть явно обозначены |
| NFR-02.03 | Кнопка подтверждения записи должна визуально отличаться в активном и неактивном состоянии |
| NFR-02.04 | При ошибке валидации система не должна очищать корректно заполненные поля формы |
| NFR-02.05 | Если выбранный слот стал недоступен, система должна сохранить корректно введенные контактные данные клиента |
| NFR-02.06 | Основной сценарий онлайн-записи должен быть доступен для прохождения на экране шириной от 360 px без горизонтальной прокрутки |

---

## 2. Производительность

### NFR-03. Скорость загрузки и отклика

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-03.01 | Главная страница сайта должна загружаться не дольше 3 секунд при стабильном интернет-соединении |
| NFR-03.02 | После выбора процедуры доступные даты должны отображаться в течение 3 секунд |
| NFR-03.03 | После выбора доступной даты свободные слоты должны отображаться в течение 3 секунд |
| NFR-03.04 | Подтверждение записи должно завершаться не более чем за 2 секунды после отправки данных клиентом |
| NFR-03.05 | При задержке ответа сервиса более 2 секунд система должна отображать индикатор ожидания |
| NFR-03.06 | При обычной нагрузке MVP система должна поддерживать не менее 10 одновременных пользователей без превышения установленных времен отклика |

---

## 3. Доступность и устойчивость сервиса

### NFR-04. Доступность онлайн-записи

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-04.01 | Онлайн-запись должна быть доступна клиенту вне зависимости от рабочего времени мастера, за исключением технических перерывов |
| NFR-04.02 | При технической ошибке система должна показать пользователю сообщение с описанием проблемы и предложением повторить действие позже |
| NFR-04.03 | Недоступность сервиса уведомлений не должна блокировать успешно сохраненную запись |
| NFR-04.04 | При сетевой ошибке система должна показать пользователю сообщение о проблеме соединения и предложить повторить действие позже |

---

## 4. Целостность и сохранность данных

### NFR-05. Согласованность данных записи

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-05.01 | Операция создания записи должна выполняться атомарно: при ошибке система не должна сохранять частично созданную запись |
| NFR-05.02 | Операция отмены записи должна выполняться атомарно: при ошибке система не должна сохранять частично измененные данные |
| NFR-05.03 | Повторная отправка запроса подтверждения записи не должна создавать дублирующую активную запись на тот же временной интервал |
| NFR-05.04 | После обновления страницы подтверждения система не должна терять данные уже созданной записи |
| NFR-05.05 | Система должна сохранять согласованность данных между расписанием, недоступными периодами и записями |

### NFR-06. Резервное копирование и восстановление

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-06.01 | Для данных о записях должно быть предусмотрено резервное копирование |
| NFR-06.02 | Для данных о записях должна быть предусмотрена возможность восстановления из резервной копии |
| NFR-06.03 | При восстановлении данных из резервной копии должны сохраняться связи между записью, процедурой, клиентом и днем расписания |

---

## 5. Логирование 

### NFR-07. Логирование ошибок

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-07.01 | Система должна фиксировать ошибки создания записи в журнале ошибок |
| NFR-07.02 | Система должна фиксировать ошибки отмены записи в журнале ошибок |
| NFR-07.04 | Запись об ошибке должна содержать дату и время события, тип ошибки и идентификатор связанной записи при его наличии |
| NFR-07.05 | Система не должна отображать пользователю технические детали ошибки |

---

## 6. Безопасность

### NFR-08. Авторизация и управление доступом

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-08.01 | Личный кабинет мастера должен быть доступен только после успешной авторизации |
| NFR-08.02 | Неавторизованный пользователь не должен получать доступ к функциям управления процедурами, расписанием и записями |
| NFR-08.03 | Система должна завершать сессию мастера после выхода из личного кабинета |
| NFR-08.04 | Система должна завершать сессию мастера по истечении установленного времени бездействия |
| NFR-08.05 | При неправильном логине или пароле система должна показывать общее сообщение об ошибке без указания, какое поле введено неверно |
| NFR-08.06 | Система должна временно блокировать вход после 5 неудачных попыток авторизации в течение 10 минут |

### NFR-09. Требования к паролю

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-09.01 | Пароль мастера должен быть длиной не менее 8 символов |
| NFR-09.02 | Система должна поддерживать парольные фразы длиной не менее 64 символов |
| NFR-09.03 | Пароль мастера должен храниться только в виде защищенного хеша |
| NFR-09.04 | Система не должна использовать подсказки к паролю и проверочные вопросы |

### NFR-10. Защита персональных данных

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-10.01 | Персональные данные клиента не должны отображаться в публичной части сайта |
| NFR-10.02 | Мастер должен получать доступ только к данным клиентов, записанных к этому мастеру |
| NFR-10.03 | Персональные данные должны передаваться по защищенному соединению HTTPS |
| NFR-10.04 | Пароль мастера должен храниться только в виде защищенного хеша |
| NFR-10.05 | Система не должна отображать технические детали ошибок, связанных с персональными данными или доступом |
| NFR-10.06 | В рамках MVP данные клиентов должны храниться на серверах, расположенных на территории Российской Федерации |

---

## 7. Совместимость

### NFR-11. Поддержка устройств и браузеров

| **ID** | **Требование** |
| ------ | -------------- |
| NFR-11.01 | Интерфейс должен корректно отображаться на мобильных устройствах, планшетах и десктопах |
| NFR-11.02 | Основной сценарий онлайн-записи должен быть доступен для прохождения на мобильном устройстве |
| NFR-11.03 | Размер интерактивных элементов на мобильных устройствах должен быть не менее 44 x 44 px |
| NFR-11.04 | Система должна корректно работать в текущей стабильной и предыдущей версии браузеров Chrome, Safari, Firefox и Edge на момент релиза |
| NFR-11.05 | Система должна корректно работать на актуальных версиях Windows, macOS, iOS и Android |
| NFR-11.06 | Основной сценарий онлайн-записи должен быть доступен при ширине экрана 360 px и выше |
