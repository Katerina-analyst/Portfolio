# Бизнес-правила

## BR-01. Правила формирования слотов

Слот - это рассчитанный системой временной интервал, доступный клиенту для записи на выбранную процедуру.
Слот не выделяется в отдельную сущность модели данных, так как рассчитывается динамически на основе дня расписания, рабочего интервала дня расписания, недоступных периодов, существующих активных записей и длительности выбранной процедуры.

### 1. Исходные данные

Для формирования слотов система использует:
- день расписания
- рабочий интервал дня расписания
- недоступные периоды дня расписания
- уже созданные активные записи
- длительность выбранной процедуры

### 2. Алгоритм формирования слотов

Для формирования слотов система выполняет следующие действия:
1. Определяет длительность выбранной процедуры
2. Находит день расписания на выбранную дату
3. Определяет рабочий интервал дня расписания

   Например: `09:00-18:00`

4. Исключает из рабочего интервала:
   - недоступные периоды дня расписания
   - интервалы уже созданных активных записей
5. Получает список свободных интервалов
6. Проверяет, помещается ли выбранная процедура в каждый свободный интервал
7. Если процедура полностью помещается в свободный интервал, система отображает клиенту доступный слот
8. Время окончания слота рассчитывается по формуле:

> end_time = start_time + duration

9. Если рассчитанное `end_time` выходит за границы свободного интервала или рабочего интервала дня расписания, такой слот не отображается клиенту

### 3. Пример формирования слотов

**Дано:**
- рабочий интервал дня расписания: `09:00-18:00`
- недоступный период: `13:00-14:00`
- уже созданная активная запись: `12:10-12:40`
- длительность выбранной процедуры: `30 минут`

Система исключает из рабочего интервала недоступный период и уже созданную активную запись.

**В результате свободные интервалы:**

- `09:00-12:10`
- `12:40-13:00`
- `14:00-18:00`

Система отображает только те слоты, где процедура длительностью `30 минут` полностью помещается в свободный интервал.

**Например:**
- слот `09:00-09:30` отображается
- слот `12:40-13:10` не отображается, потому что пересекается с недоступным периодом `13:00-14:00`
- слот `17:30-18:00` отображается
- слот `17:45-18:15` не отображается, потому что выходит за границы рабочего интервала

## BR-02. Правила онлайн-записи

- Запись создается только после подтверждения клиентом и повторной проверки доступности выбранного слота
- Система не должна создавать две активные записи на один и тот же временной интервал
- После создания записи выбранный временной интервал больше не отображается другим клиентам как доступный слот
- Ссылка для просмотра и отмены записи формируется системой на основе уникального токена доступа к записи
- После наступления времени начала записи отмена записи по ссылке недоступна
- При создании записи система фиксирует стоимость выбранной процедуры на момент записи
- Клиент может подтвердить запись только после выбора категории, процедуры, доступной даты, свободного слота, корректного заполнения имени и номера телефона и подтверждения согласия на обработку персональных данных

---

## BR-03. Правила статусов процедур

- Процедура со статусом `available` доступна для онлайн-записи
- Процедура со статусом `unavailable` не отображается клиенту как доступная для записи
- В MVP мастер не создает новые категории процедур, а выбирает направление из справочника

---

## BR-04. Правила отмены записи мастером или клиентом

- При отмене записи статус записи изменяется на `canceled`
- При отмене записи соответствующий временной интервал снова может отображаться как доступный слот, если это не противоречит правилам формирования слотов
- После отмены записи мастером система инициирует отправку уведомления клиенту
- После отмены записи клиентом система инициирует отправку уведомления мастеру
- После наступления времени начала записи отмена записи клиентом по ссылке недоступна
- Физическое удаление записи в MVP не используется
- Отмененная запись не отображается в календаре записей мастера как активная

---

## BR-05. Правила уведомлений

- Уведомления клиенту и мастеру инициируются после создания записи
- Уведомление клиенту инициируется после отмены записи мастером
- Уведомление мастеру инициируется после отмены записи клиентом
- Напоминание клиенту о визите инициируется за 24 часа до времени визита
- Новое уведомление создается со статусом `created`
- После попытки отправки уведомления система обновляет статус уведомления
- Если уведомление не отправлено, система фиксирует ошибку отправки
- Ошибка отправки уведомления не отменяет созданную или отмененную запись
- В MVP шаблоны уведомлений хранятся на стороне backend-приложения
- Система формирует итоговый текст уведомления на backend на основании:
   - типа уведомления;
   - данных записи;
   - данных процедуры;
   - данных клиента или мастера;
   - токена доступа к записи.
- В таблице `notifications` хранится уже сформированный итоговый текст уведомления в поле `message_text`

## BR-06. Правила каналов связи

- В MVP для клиента основным каналом связи является номер мобильного телефона
- При онлайн-записи клиент вводит номер телефона, и система сохраняет его как канал связи клиента с типом `phone`, значением номера телефона, статусом `active` и признаком `is_default = true`
- Мастер не создает новые типы каналов связи в MVP
- Мастер выбирает тип канала связи из преднастроенного справочника
- Мастер может заполнить значение канала связи и включить или отключить его отображение
- Клиент видит только активные и заполненные каналы связи мастера
- Отключенный канал связи мастера не отображается клиенту
- Канал связи мастера без заполненного значения не отображается клиенту
- У мастера может быть выбран один канал связи по умолчанию

---

## BR-07. Правила пользователей, регистрации и доступа

- Клиент не проходит регистрацию и не имеет личного кабинета в MVP
- При онлайн-записи система создает пользователя с `user_type = client`
- Мастер имеет заранее созданную учетную запись с `user_type = master`
- Неавторизованный пользователь не получает доступ к личному кабинету мастера
- Самостоятельное восстановление пароля мастера в MVP не предусмотрено. Для восстановления доступа мастер обращается к администратору

---

## BR-08. Правила настройки расписания

- Если мастер переводит день расписания в рабочий, он должен указать время начала и окончания работы
- Если мастер переводит день расписания в нерабочий, система очищает или не учитывает время начала и окончания работы для этого дня
- Если день расписания имеет признак `is_working = false`, система не формирует и не отображает слоты на эту дату
- Периоды расписаний одного мастера не должны пересекаться
- Недоступный период должен находиться внутри рабочего интервала дня расписания
- Недоступные периоды внутри одного дня расписания не должны пересекаться
