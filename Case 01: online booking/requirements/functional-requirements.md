# Функциональные требования

## 1. Онлайн-запись клиента на процедуру

### FRQ-01. Просмотр и выбор направлений и процедур

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-01.01 | Система должна отображать клиенту список доступных направлений процедур |
| FRQ-01.02 | Система должна позволять клиенту выбрать направление процедур |
| FRQ-01.03 | Система должна отображать список процедур выбранного направления |
| FRQ-01.04 | Система должна отображать только доступные для онлайн-записи процедуры |
| FRQ-01.05 | Система должна отображать клиенту название, краткое описание, стоимость и длительность процедуры |

### FRQ-02. Выбор даты и времени

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-02.01 | Система должна отображать клиенту доступные даты для выбранной процедуры |
| FRQ-02.02 | Система должна позволять клиенту выбрать дату визита |
| FRQ-02.03 | Система должна отображать свободные временные слоты на выбранную дату |
| FRQ-02.04 | Система не должна отображать забронированные или недоступные как свободные для бронирования |
| FRQ-02.05 | Система должна позволять клиенту выбрать свободный временной слот |
| FRQ-02.06 | Система должна повторно проверять доступность выбранного слота перед временным бронированием |
| FRQ-02.07 | Если выбранный слот стал недоступен, система должна сообщить об этом клиенту и предложить выбрать другой слот |
| FRQ-02.08 | Система должна временно забронировать выбранный слот до завершения записи или отмены процесса (слот переводится в статус "Недоступен") |
| FRQ-02.09 | Система должна перевести слот в статус "Забронирован" после создания записи на процедуру |

### FRQ-03. Подтверждение параметров записи

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-03.01 | Система должна отображать клиенту выбранные параметры записи: направление процедуры, процедуру, стоимость, длительность, дату и время визита |
| FRQ-03.02 | Система должна позволять клиенту подтвердить выбранные параметры записи |
| FRQ-03.03 | Система должна позволять клиенту редактировать параметры записи, посредством возврата на шаг назад на любом этапе записи |
| FRQ-03.04 | При изменении параметров записи система должна освобождать ранее временно забронированный слот |
| FRQ-03.05 | Система должна позволять клиенту отменить процесс онлайн-записи до создания записи |

### FRQ-04. Ввод контактных данных

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-04.01 | Система должна отображать клиенту форму ввода контактных данных |
| FRQ-04.02 | Система должна позволять клиенту ввести имя и номер телефона |
| FRQ-04.03 | Система не должна требовать регистрации клиента для создания записи |
| FRQ-04.04 | Система должна проверять заполнение обязательных полей |
| FRQ-04.05 | Если контактные данные заполнены некорректно, система должна подсвечивать поля с ошибками |
| FRQ-04.06 | Система должна позволять клиенту исправить контактные данные и повторно отправить форму |

### FRQ-05. Создание записи

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-05.01 | Система должна создавать запись после подтверждения параметров записи и отправки корректных контактных данных |
| FRQ-05.02 | Система должна связывать запись с клиентом, мастером, процедурой и выбранным слотом |
| FRQ-05.03 | Система должна изменять статус выбранного слота так, чтобы он не отображался другим клиентам как свободный |
| FRQ-05.04 | После успешного создания записи система должна отображать клиенту подтверждение успешной записи |
| FRQ-05.05 | В подтверждении успешной записи система должна отображать направление процедуры, название процедуры, стоимость процедуры, длительность процедуры, дату и время визита |
| FRQ-05.06 | После завершения записи система должна инициировать отправку уведомлений мастеру и клиенту |
| FRQ-05.07 | Если запись не удалось создать, система должна сообщить клиенту об ошибке и не сохранять некорректную запись |

## 2. Авторизация мастера

### FRQ-06. Вход в личный кабинет мастера

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-06.01 | Система должна отображать мастеру форму авторизации по его ссылке для входа |
| FRQ-06.02 | Система должна позволять мастеру ввести логин и пароль  |
| FRQ-06.03 | Система должна проверять корректность логина и пароля |
| FRQ-06.04 | Если логин и пароль корректны, система должна авторизовать мастера |
| FRQ-06.05 | После успешной авторизации система должна открывать личный кабинет мастера |
| FRQ-06.06 | Если логин или пароль некорректны, система должна подсветить ошибки или сообщить, что данные для входа неверные |
| FRQ-06.07 | Если превышено количество попыток входа, система должна временно ограничивать повторные попытки |
| FRQ-06.08 | Неавторизованный пользователь не должен получать доступ к личному кабинету мастера |

## 3. Управление процедурами

### FRQ-07. Управление направлениями и процедурами

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-07.01 | Система должна позволять мастеру создавать процедуру |
| FRQ-07.02 | Система должна позволять мастеру редактировать или вносить название, краткое описание, стоимость, длительность и статус процедуры |
| FRQ-07.03 | Система должна позволять мастеру привязать процедуру к направлению |
| FRQ-07.04 | Процедура со статусом “Доступна” должна отображаться клиентам |
| FRQ-07.05 | Процедура со статусом “Недоступна” не должна отображаться клиентам |
| FRQ-07.06 | Система должна позволять мастеру просматривать список созданных процедур |

## 4. Настройка расписания

### FRQ-08. Управление расписанием и недоступными периодами

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-08.01 | Система должна позволять мастеру указывать рабочие дни |
| FRQ-08.02 | Система должна позволять мастеру указывать время начала и окончания рабочего дня |
| FRQ-08.03 | Временной слот должен полностью помещаться в рабочий интервал мастера |
| FRQ-08.04 | Система должна позволять мастеру добавлять недоступные периоды |
| FRQ-08.05 | Система должна позволять мастеру изменять недоступные периоды |
| FRQ-08.06 | Система должна учитывать расписание мастера при формировании доступных слотов |
| FRQ-08.07 | Система должна учитывать недоступные периоды при формировании доступных слотов |
| FRQ-08.08 | Система не должна отображать клиентам слоты в недоступные периоды, до начала и после окончания рабочего дня |

## 5. Управление записями

### FRQ-09. Просмотр и отмена записей мастером

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-09.01 | Система должна позволять мастеру просматривать календарь записей |
| FRQ-09.02 | Система должна позволять мастеру выбирать период просмотра календаря записей |
| FRQ-09.03 | Система должна позволять мастеру просматривать карточку записи |
| FRQ-09.04 | Система должна отображать в карточке записи: процедуру, длительность, стоимость, дату, время визита и контактные данные клиента |
| FRQ-09.05 | Система должна позволять мастеру отменить запись |
| FRQ-09.06 | При отмене записи система должна изменять статус записи на “Отменена” |
| FRQ-09.07 | При отмене записи система должна освобождать связанный слот |
| FRQ-09.08 | При отмене записи система должна отобразить мастеру подтверждение отмены |
| FRQ-09.09 | При отмене записи система должна инициировать отправку уведомления об отмене клиенту |

## 6. Уведомления

### FRQ-10. Отправка уведомлений

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-10.01 | Система должна инициировать отправку уведомления с подтверждением записи клиенту после создания записи |
| FRQ-10.02 | Система должна инициировать отправку уведомления о новой записи мастеру после создания записи |
| FRQ-10.03 | Система должна инициировать отправку уведомления об отмене записи клиенту |
| FRQ-10.04 | Система должна инициировать отправку напоминания клиенту о визите за 24 часа до визита |
| FRQ-10.05 | Система должна хранить статус отправки уведомления |
| FRQ-10.06 | Система должна логировать ошибки отправки уведомлений |
| FRQ-10.07 | Если уведомление не отправлено по основному каналу, система должна зафиксировать ошибку и передать информацию мастеру или во внутренний канал |
| FRQ-10.08 | Система должна фиксировать дату и время создания уведомления |
| FRQ-10.09 | Система должна фиксировать дату и время отправки уведомления |

## 7. Управление профилем мастера

### FRQ-11. Управление профилем мастера и каналами связи

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-11.01 | Система должна позволять мастеру изменить своё имя |
| FRQ-11.02 | Система должна отображать мастеру список доступных типов каналов связи |
| FRQ-11.03 | Система должна позволять мастеру указать или изменить значение канала связи |
| FRQ-11.04 | Система должна позволять мастеру включить канал связи |
| FRQ-11.05 | Система должна позволять мастеру отключить канал связи |
| FRQ-11.06 | Система должна позволять мастеру выбрать канал связи по умолчанию |
| FRQ-11.07 | Система должна отображать клиенту только активные каналы связи мастера |
| FRQ-11.08 | Если канал связи отключен или значение канала не заполнено, система не должна отображать его клиенту |

## 8. Связь с мастером

### FRQ-12. Отображение каналов связи

| **ID** | **Требование** |
| -------- | ------------ |
| FRQ-12.01 | Система должна отображать клиенту активные каналы связи с мастером на главной странице сайта |
| FRQ-12.02 | Система должна отображать только активные каналы связи мастера |
| FRQ-12.03 | При выборе канала email система должна открывать создание письма на адрес мастера |
| FRQ-12.04 | При выборе канала телефона система должна открывать набор номера мастера |
| FRQ-12.05 | При выборе канала VK система должна открывать страницу мастера во VK |
| FRQ-12.06 | При выборе канала MAX система должна открывать канал связи мастера в MAX |
