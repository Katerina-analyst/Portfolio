# Функциональные требования

## 1. Онлайн-запись клиента на процедуру

### FRQ-01. Просмотр и выбор категорий и процедур

| **Идентификатор** | **Описание** | **Источник** |
|---|---|---|
| FRQ-01.01 | Система должна отображать клиенту список доступных категорий процедур | BR-PROCEDURE-03 |
| FRQ-01.02 | Система должна позволять клиенту выбрать категорию процедур | BR-PROCEDURE-03, BR-BOOKING-09 |
| FRQ-01.03 | Система должна отображать список процедур выбранной категории | UC-01 |
| FRQ-01.04 | Система должна отображать только процедуры, доступные для онлайн-записи | BR-PROCEDURE-01, BR-PROCEDURE-02 |
| FRQ-01.05 | Система должна отображать клиенту название, краткое описание, стоимость и длительность процедуры | UC-01 |

### FRQ-02. Выбор даты и времени

| **Идентификатор** | **Описание** | **Источник** |
|---|---|---|
| FRQ-02.01 | Система должна определять доступные даты после выбора процедуры | BR-SCHEDULE-04 |
| FRQ-02.02 | Система должна отображать клиенту доступные даты для выбранной процедуры | BR-SCHEDULE-04 |
| FRQ-02.03 | Система должна позволять клиенту выбрать доступную дату визита | BR-BOOKING-09, BR-SCHEDULE-04 |
| FRQ-02.04 | После выбора даты система должна определить день расписания на выбранную дату | BR-SCHEDULE-03, BR-SCHEDULE-04 |
| FRQ-02.05 | Если день расписания не найден или является нерабочим, система должна возвращать пустой список свободных слотов | BR-SCHEDULE-03 |
| FRQ-02.06 | Для рабочего дня система должна определить свободные временные интервалы с учетом рабочего интервала, недоступных периодов и активных записей | BR-SLOT-01–BR-SLOT-04 |
| FRQ-02.07 | Система не должна формировать слот, если длительность свободного временного интервала меньше длительности выбранной процедуры | BR-SLOT-07 |
| FRQ-02.08 | Продолжительность каждого слота должна соответствовать продолжительности выбранной процедуры | BR-SLOT-05 |
| FRQ-02.09 | Первый слот должен начинаться со времени начала свободного временного интервала | BR-SLOT-08 |
| FRQ-02.10 | Время окончания слота должно рассчитываться как сумма времени начала слота и продолжительности выбранной процедуры | BR-SLOT-06 |
| FRQ-02.11 | Каждый следующий слот должен начинаться со времени окончания предыдущего слота | BR-SLOT-09 |
| FRQ-02.12 | Система должна формировать только слоты, полностью находящиеся внутри свободного временного интервала | BR-SLOT-02, BR-SLOT-07 |
| FRQ-02.13 | Система должна объединять слоты из всех свободных временных интервалов и сортировать их по времени начала по возрастанию | BR-SLOT-01–BR-SLOT-09 |
| FRQ-02.14 | Система должна отображать клиенту сформированный список свободных слотов на выбранную дату | UC-01, BR-BOOKING-09 |
| FRQ-02.15 | Система должна позволять клиенту выбрать свободный слот | BR-BOOKING-09 |
| FRQ-02.16 | Перед созданием записи система должна повторно проверить доступность выбранного слота | BR-BOOKING-02–BR-BOOKING-04 |
| FRQ-02.17 | Если выбранный слот стал недоступен, система должна сообщить об этом клиенту и предложить выбрать другой свободный слот | UC-01, BR-BOOKING-02–BR-BOOKING-04 |

### FRQ-03. Ввод контактных данных и согласия

| **Идентификатор** | **Описание** | **Источник** |
|---|---|---|

| FRQ-03.03 | Система не должна требовать регистрации клиента для создания записи | BR-USER-01 |

| FRQ-03.05 | Система должна проверять корректность имени и номера телефона | BR-BOOKING-08 |
| FRQ-03.06 | Система должна отображать клиенту чекбокс согласия на обработку персональных данных | BR-BOOKING-10 |
| FRQ-03.07 | Система должна фиксировать согласие клиента на обработку персональных данных | BR-BOOKING-10 |

### FRQ-04. Подтверждение записи

| **Идентификатор** | **Описание** | **Источник** |
|---|---|---|
| FRQ-04.01 | Система должна позволять клиенту подтвердить запись после выбора категории, процедуры, доступной даты и свободного слота, корректного заполнения имени и номера телефона и предоставления согласия на обработку персональных данных | BR-BOOKING-01, BR-BOOKING-08, BR-BOOKING-09, BR-BOOKING-10 |
| FRQ-04.02 | Система должна позволять клиенту изменять параметры записи до ее подтверждения | UC-01 |
| FRQ-04.03 | Система должна позволять клиенту прервать процесс онлайн-записи до подтверждения | UC-01 |
| FRQ-04.04 | Система не должна позволять клиенту подтвердить запись, если обязательные данные отсутствуют или заполнены некорректно, не выбран свободный слот или не предоставлено согласие на обработку персональных данных | BR-BOOKING-08, BR-BOOKING-09, BR-BOOKING-10 |

### FRQ-05. Создание записи

| **Идентификатор** | **Описание** | **Источник** |
|---|---|---|
| FRQ-05.01 | Система должна создавать запись после подтверждения клиентом формы онлайн-записи | BR-BOOKING-01 |
| FRQ-05.02 | Система должна связывать созданную запись с клиентом, процедурой и днем расписания, а также сохранять время начала и окончания визита | UC-01 |
| FRQ-05.03 | Система должна сформировать и связать с созданной записью уникальный токен доступа | BR-BOOKING-05 |
| FRQ-05.04 | После успешного создания записи система должна отображать клиенту подтверждение успешной записи | UC-01 |
| FRQ-05.05 | После создания записи система должна формировать уникальную ссылку для просмотра и отмены записи | BR-BOOKING-05, BR-BOOKING-06 |
| FRQ-05.06 | После создания записи система должна инициировать отправку уведомлений клиенту и мастеру | BR-NOTIFY-01 |
| FRQ-05.07 | Если запись не удалось создать, система должна сообщить клиенту об ошибке | UC-01 |
| FRQ-05.08 | При создании записи система должна сохранять стоимость процедуры, действующую на момент создания записи | BR-BOOKING-07 |
